# MOBILAINISHA 7.5 — сквозной ремонт (разработка)
Начало: 15.11.2026. Ветка: `feature/repair-workflow-v75`. Текущая опубликованная v74 не заменяется.

## Зафиксированное по образцам актов
**Приёмка:** исполнитель/реквизиты, номер заказа, дата и время, ФИО и контакты заказчика, адрес при необходимости, устройство, IMEI/серийный номер, комплектность, внешний вид, предоплата, предварительная стоимость, неисправность со слов клиента, условия диагностики, подписи обеих сторон. Обязательная фиксация 6 сторон либо непрерывное видео и крупные планы дефектов.
**Выдача:** тот же номер, заказчик, устройство, комплектность, серийный номер, даты приёмки/выдачи, выполненные работы и запчасти, сумма/предоплата/остаток, гарантийные условия, проверка, состояние и доказательства передачи, подписи. Юридический текст старых бланков подлежит проверке, не копируется автоматически.

## Статусы
requested → intake_pending → accepted → diagnostics → approval_pending → approved → repairing ↔ waiting_parts → quality_check → ready → payment_pending → handover_pending → issued.
Отказ клиента: rejected → returned_unrepaired. Согласование стоимости и выбора оригинал/совместимая деталь обязательно до работ; изменение условий требует нового решения клиента. Мастер ведёт штатные стадии без одобрения управляющего.

## Матрица сквозной проверки
- [ ] Клиент регистрируется по телефону с OTP и по почте с подтверждением; права проверяются сервером.
- [ ] Клиент создаёт заявку на телефоне A, мастер магазина видит её на телефоне B.
- [ ] Продавец оформляет приёмку, обязательные фото/видео, клиент подписывает акт, печать A4 и электронный экземпляр.
- [ ] Мастер начинает диагностику, уведомления и история статусов приходят клиенту.
- [ ] Мастер предлагает работу/цену/срок/запчасть/гарантию с медиа, клиент соглашается или отказывает.
- [ ] Ожидание деталей, работа, контроль качества, готовность и оплата подтверждаются по отдельности.
- [ ] Выдача только после подтверждённой передачи, фото/видео, акта и фиксации получателя.
- [ ] Жалобы и запросы ответов видят мастер, управляющий, владелец; история сохраняется.
- [ ] Продажи: каталог, остатки, корзина, резерв, заказ, платёж, чек, выдача.
- [ ] Смены, перемещения, закупки, зарплаты, инвентаризация, отчёты по утверждённым правилам.

## Ограничения и порядок
Существующий Supabase размещён в eu-west-1. Пока не решён вопрос соответствия требованиям обработки персональных данных РФ, **не сохранять реальные клиентские данные в этот проект**. Файл SQL — только проект схемы, не выполнен. Перед применением: политики RLS по ролям и магазинам, защита файлов, номера через транзакционную последовательность, миграции и автоматизированные тесты. Реальная подпись, push, платежи и касса требуют отдельных защищённых интеграций.
